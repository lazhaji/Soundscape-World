# Soundscape Railway

移动端声音空间个人作品集。产品需求以 [`docs/PRD.md`](docs/PRD.md) 为首要依据。

当前实现 **M0：项目初始化与技术验证**。页面展示固定约 45° 正交相机下的程序化底座与建筑盒体，支持点击底座显示触点，并在用户点击后播放本地生成的低音量白噪音。它是技术原型，尚未实现可探索便利店、列车流程、空间音景、档案、社交或 PWA 离线能力。

## 本地运行

需要 Node.js 22.13+（22.x）或 24.x；本轮环境为 Node.js 24.12.0 / npm 11.6.2。直接依赖使用精确版本，完整依赖树由 `package-lock.json` 锁定。TypeScript 固定 5.9.3，以满足当前 TypeScript ESLint 的兼容范围。

```bash
npm ci
npm run dev
```

打开终端显示的本地地址（默认 `http://127.0.0.1:5173`）：

1. 确认显示 Demo 占位模型；初次进入保持静音。
2. 点击建筑前方的底座，查看圆环与 X/Z 触点反馈；相机固定不旋转。
3. 调低设备音量后点击「点击启声」，试听本机生成的白噪音。
4. 点击「重新加载场景」，确认声音继续；点击「停止试听」，确认静音。重复启停不会新建 AudioContext。

手机联调可运行 `npm run dev -- --host 0.0.0.0`，在同一局域网访问电脑 IP 和终端端口。允许防火墙访问时只开放所需的本地开发端口。这里的手机步骤需要实际设备执行，不等同于桌面移动模拟。

## 检查与构建

```bash
npm run lint
npm run typecheck
npm run test
npm run build
npm run preview
```

`build` 先检查类型，再输出 `dist/` 静态文件；`preview` 默认使用 `http://127.0.0.1:4173`。资源路径采用相对 base，便于以后部署到子目录。直接双击 HTML 不属于支持的运行方式。

单元测试使用 Vitest，覆盖手势启动、重复启声去重、取消和重试、浏览器中断、音频节点释放及白噪音取值。浏览器验证记录、手工步骤和实机限制见 [`docs/TEST_PLAN.md`](docs/TEST_PLAN.md)。

## M0 源码结构

- `src/app/`：最小技术验证页面。
- `src/world/`：按需加载的 R3F 场景、固定相机、触点、加载/错误重试。
- `src/audio/`：应用级单实例 AudioEngine、本地白噪音生成；不随 React 组件卸载而销毁。
- `src/ui/`：音频验证面板与错误边界。
- `tests/unit/`：M0 单元测试。
- `public/`：项目原创图标；参考 PNG/MP4 不会打入发布包。

## 已知边界

- 占位建筑不能进入；触点圆环不是可移动角色。没有区域检测或空间混音。
- 声音启动与 WebGL 失败会显示提示；音频解锁等待最多 10 秒，3D 初始化等待最多 12 秒。后台音频被中断时需再次点击启声，无法保证锁屏播放。
- 3D 使用按需渲染和 DPR 1–1.5；没有持续动画，支持减少动态效果设置。真实手机性能、扬声器听感与 Safari 兼容性仍需实测。
- 尚无 Service Worker、离线缓存、数据库或持久化功能。后续只能按里程碑推进。
- 初始目录未包含 `.git`；本轮没有创建提交或设置远程仓库。
- 当前构建的 3D 按需模块约 914 KB（gzip 243 KB），会触发 Vite 的 500 KB 警告；未提高阈值隐藏警告。R3F 9.8.1 内部使用 `THREE.Clock`，在 Three.js 0.186.1 中产生弃用警告；当前浏览器验证无应用错误。

## 项目资料与后续开发

1. 将本资料包解压到你准备作为 `soundscape-railway` 的项目仓库根目录。
2. 若已存在源码：复制并合并文档与参考素材，谨慎处理同名文件，勿覆盖已有代码或 `AGENTS.md` 的有效规则。
3. 在 Codex 中打开这个仓库。
4. `CODEX_START.md` 保留为 M0 原始任务说明；继续开发前先阅读 `docs/TASKS.md` 的当前进度。
5. 检查运行与测试报告，验收后再逐个授权 M1–M7。
